`agent_directives.md`(상시 로딩)의 R07/R09/R11은 트리거 조건과 포인터만 보유한다. 적용 시점에 이 문서를 참조하여 아래 상세 절차를 따른다.

## R07: MODEL_TIERING (모델 티어링 상세)

Agent 도구로 서브에이전트를 디스패치할 때, 복잡도에 따라 `model` 파라미터를 명시한다.

| 모델 | 대상 작업 | 근거 |
|------|----------|------|
| **opus** | 학습 설계·판정 정책 설계, 다중 모듈 리팩토링, 검증기 오탐/미탐·진도 유실의 근본 원인 추적 | 깊은 추론 필요 |
| **sonnet** | 코드 탐색(Explore), 오류 수정, `node --test` 작성/실행, 환각 검증, 플랫폼 동작 확인 | 패턴 매칭 + 중간 추론 |
| **haiku** | 코드 리뷰, 파일 정리, 문서 패치, 단순 grep/glob, 컨텍스트 사전 수집(R11) | 구조화된 체크리스트 실행 |

- Plan Mode의 **Explore 에이전트**는 `model: "sonnet"`.
- Plan Mode의 **Plan 에이전트**는 `model: "opus"`.
- 모호하면 **sonnet** 기본값.

## R09: DEADLOCK_ESCAPE (교착상태 탈출 상세)

동일 접근법이 반복 실패하여 진전이 없는 상태를 교착으로 정의하고, 아래 기준에 따라 자동 탈출한다.

### 감지 기준 (시도 횟수 기반)
| 교착 패턴 | 트리거 | 탈출 행동 |
|-----------|--------|----------|
| 동일 에러 반복 | 같은 접근법 **2회 실패** | 접근법 전환 (다른 경로/도구/전략) |
| 탐색 순환 | 같은 파일군 **3회 이상** 재탐색 | 탐색 중단, 현재까지 파악 내용 정리 |
| 수정→실패 루프 | 수정 후 동일 오류 **3회 반복** | STOP, 근본 원인 재분석 (investigator 디스패치) |
| 대안 고갈 | 서로 다른 접근법 **2개 이상** 실패 | 사용자에게 즉시 보고 및 방향 질문 |

### 탈출 절차 (RECITE-PIVOT)
1. **RECITE (목표 복창):** 현재 작업의 최종 목표를 한 문장으로 복창.
2. **DIAGNOSE (원인 요약):** 실패한 접근법과 원인을 1~2줄로 요약.
3. **PIVOT (전환):** (a) 다른 접근법으로 재시도 / (b) investigator 디스패치 / (c) 사용자 보고 후 대기.

### Edit 도구 장애 우회
- Edit 1회 실패 시, 대상 파일을 Read로 다시 읽어 현재 상태를 확인한 후 정확한 `old_string`으로 재시도한다.
- 2회 연속 실패하면 즉시 Bash(sed 또는 node 스크립트)로 우회한다. 3회 이상 재시도 금지.

### 금지 행동
- 같은 명령어를 매개변수만 미세 변경하여 3회 이상 재시도 금지.
- sleep/wait 후 동일 시도 반복 금지.
- 에러 메시지를 무시하고 다음 단계 진행 금지.

## R11: PREFETCH_WITH_LITE (경량 모델 사전 정제 상세)

복잡 작업에서 Opus/Sonnet 디스패치 **전에**, Haiku 에이전트로 구조화 정보를 먼저 수집해 컨텍스트를 압축한다(추론 위임 금지).

### 위임 범위 (추출만, 추론 금지)
- 대상 모듈의 파일 인벤토리 및 라인 수
- `export` 시그니처(이름·파라미터·반환) 목록
- import/export 의존 관계 정리
- grep 결과 필터링 및 구조화

### 위임하지 않는 작업
- 신뢰경계·격리 판단, 버그 근본 원인 분석, 아키텍처 설계, 코드 리뷰 소견

### 호출 패턴
`Agent(model="haiku", prompt="아래 모듈의 파일 목록·export 시그니처·import 관계를 정리하라: {모듈 경로}")`
→ 결과를 후속 Opus/Sonnet 에이전트 prompt에 주입.

### 생략 조건
- 대상 파일이 3개 이하로 명확한 경우 직접 Read가 더 효율적이므로 생략한다. (`dojo/`는 파일당 소규모이므로 대개 생략 대상)
